# TMNT Engine v1.6 — Relatório de validação

**Data:** 2026-10-20. **Escopo:** núcleo universal, legado, proteção de ambientes e apps do worker, PostHog, segurança em laboratório.

## Alterações realizadas

- Corrigida falha de isolamento: a reserva de fila agora requer allowlist de ambientes **e** de `tenant/app/environment`.
- Migração aditiva `0006_scoped_worker_claim.sql`; sem alterações no schema de produção. A função `r3_v1_claim_job` anterior foi preservada para compatibilidade; o worker novo utiliza exclusivamente a função restrita.
- Rejeição antes de qualquer envio/supressão se um adaptador retornar trabalho fora do escopo.
- Desabilita retirada de fila se não houver provedores OneSignal configurados.
- PostHog com HMAC obrigatoriamente; falha fechada se faltar segredo.
- Testes de ambiente, escopo multiapp, concorrência e telemetria adicionados.

## Evidência local

- `npm test`: **242/242** (105 modernos, 137 legados).
- `npm run smoke`: **21/21** verificações HTTP legadas; Neon não conectado nesse processo.
- `npm run check`: **PASS**.
- `npm run load:smoke`: 5.000 eventos sintéticos em memória, 20 duplicatas rejeitadas. **Não é teste de carga Neon.**
- `npm run demo:multiapp`: três verticais usando eventos distintos.

## Evidência em PostgreSQL real

- Projeto de homologação: `R3ENGINE-staging`; branch isolada `<redacted>`.
- Nova função SQL criada na branch; nenhum SQL executado contra o branch principal.
- Com jobs em `staging` e `test`, worker de staging reservou somente staging, preservando a outra fila sem tentativas.
- Dois apps no mesmo ambiente `test`: trabalhador autorizado apenas a `tmnt16/otherapp/test` reservou `otherapp`; `tmnt16/workerlab/test` continuou `reserved`, 0 tentativas.
- Três workers concorrentes para `tmnt16/workerlab/test`: **exatamente 1 reivindicação**. Nenhum envio real efetuado.
- Limite de branches Neon atingido; reutilizada branch QA existente, sem criar ou excluir branches.

## Pendências que NÃO estão verdes

- Driver `@neondatabase/serverless`: a importação real ainda falha (`ERR_MODULE_NOT_FOUND`; npm registry `EAI_AGAIN`), portanto teste SDK com DB real ainda não executado ponta a ponta.
- OneSignal real em aparelhos iOS/Android/Web, registro de assinaturas, permissionamento e confirmação de entrega.
- PostHog de produção e análise de lift estatístico e retenção D1/D7/D30 em população real.
- Segurança operacional, RBAC/tenants, observabilidade de incidentes, limites de taxa, testes de carga SQL e recuperação.

**Conclusão:** correção de isolamento aprovada em laboratório; não equivale a produção 10/10. Mantidos envios reais desativados.
